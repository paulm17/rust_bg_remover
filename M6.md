# M6 — CarveKit BASNet, DeepLabV3 and TRACER-B7

M6 is implemented against the checked-out CarveKit source at
`f141a311af67fb1da64269c508a6d1f786420801`. The wrappers were inspected
directly before writing the adapters:

- BASNet resizes to 320×320, divides the resized RGB array by its global
  maximum, applies ImageNet mean/std, selects the first of eight outputs, then
  uses optional per-image min/max and bicubic restoration.
- DeepLabV3 uses `PIL.Image.thumbnail((1024,1024), resample=3)` (Pillow
  bicubic), ImageNet
  normalization and `network(...)["out"][0].argmax(0)`. The exported graph is
  the actual 21-class ResNet-101 checkpoint (VOC ordering); class 0 is
  background and classes 1–20 are foreground. The manifest records all 21
  labels. Rust restores the class decision with nearest-neighbour so it stays
  binary until an explicit refiner.
- TRACER-B7 uses 640×640, ImageNet normalization and direct sigmoid soft-mask
  output with bilinear restoration. Its internal q=.1 channel threshold was
  exported as equivalent static sorted linear interpolation because
  `torch.quantile` is not an ONNX operator in the pinned exporter; PyTorch vs
  ONNX max error is below 1.5e-7 on the parity corpus.

The unavailable `TracerHair` checkpoint is not present in the registry.

## Level-2 parity and accepted report

`tests/fixtures/m6` contains 18 tracked cases: 3×2, 2×3 and 1025×3 geometries in
low `[0,64]` and high `[192,255]` encoded RGB ranges for each adapter. Every
case retains decoded RGB, complete preprocessed tensor, raw output, restored
alpha and final straight-alpha cutout. The accepted Python/ONNX report is
`tests/fixtures/m6/python-onnx-parity.json`, SHA-256
`cae8c519227ad2427d9fd3c512b9bab246f87d83944868ac7205dd2d616590ae`; all 18
records pass. Measured raw PyTorch-vs-ONNX bounds are max `2.4139881e-4`
(BASNet low-range quantization), mean `6.09292e-7`; the report gate is max
`1e-3`, mean `2e-6`. The Rust-vs-CarveKit fixture test measures BASNet tensor
max `4.77e-7`, DeepLab tensor max `0`, TRACER tensor max `1.67e-6`, and raw
output max `2.396e-4`; the JSON declares and the Rust test enforces both max
and mean bounds, including the tight `1e-5` TRACER tensor bound (normalized
ImageNet units, equivalent to less than one encoded input code).
Restored alpha is checked against declared max/mean tolerance `1/255 + 1e-6`;
final cutouts require exact RGB bytes and alpha within one uint8 code (mean
below 0.1 code), while every tracked artifact path and SHA-256 is inventory-
checked.
Before fixture generation, the script fail-closed verifies CarveKit HEAD
`f141a311af67fb1da64269c508a6d1f786420801`, torch 2.6.0, torchvision 0.21.0,
Pillow 12.3.0, numpy 2.5.2, ONNX Runtime 1.23.2, all three source-checkpoint
SHA-512 values, and all three exported-ONNX SHA-256 values; the verified
provenance is retained in the JSON report, including tracked-source
cleanliness and wrapper SHA-256 values. Report paths are portable logical
paths; set `M6_CHECKPOINT_ROOT` to select the external checkpoint directory
(default `/private/tmp/m6-checkpoints`).

Run parity generation with the task-scoped pinned environment:

```sh
PYTHONPATH=/private/tmp/m6-py312-torch:/private/tmp/m5-py312-pinned:$PWD/projects/python/image-background-remove-tool \
  /opt/homebrew/bin/python3.12 tests/fixtures/m6/generate_carvekit_parity.py
```

## Deterministic raw-alpha tournament

The report command compares U2-Net, IS-Net, BASNet, DeepLabV3 and TRACER with
the same canonical geometry, unrefined raw alpha, original RGB and straight
alpha downstream settings:

```sh
ORT_DYLIB=/private/tmp/m5-py312-pinned/onnxruntime/capi/libonnxruntime.1.23.2.dylib \
  cargo run -p bgremove-bench --offline --locked -- m6-smoke \
  --input test_images/reference/1.png \
  --reference test_images/photoroom/1.png --output runs/m6-carvekit
```

The accepted CPU report is `runs/m6-carvekit/report.json`, SHA-256
`e092c097433c779e5abbf77e4f88bb0717291ec9fbdf4740c21e3e853c3c4e2d`. All
five tournament runs (general U2-Net, IS-Net, BASNet, DeepLabV3 and TRACER-B7)
ran successfully with truthful `CPUExecutionProvider` metadata. The original
RGB input is paired with the PhotoRoom RGBA alpha reference; every run records
alpha MAE and soft IoU under the report's shared formulas, plus identical
raw-alpha/no-refiner downstream settings and the explicit hard DeepLab gate.

verification occurs before session creation; NaN/Inf outputs are rejected and
constant min/max tensors safely become zero.
