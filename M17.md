# M17 — performance, packaging and production hardening

M17 adds `bgremove-bench m17-smoke`. It benchmarks providers in deterministic
CPU-first order when an input and an explicitly configured `ORT_DYLIB` are
available. It never downloads model weights. CoreML and CUDA use the existing
ORT provider adapters; OpenVINO is reported as unavailable in this build.

## Invocation

```sh
CARGO_BUILD_JOBS=1 RAYON_NUM_THREADS=1 OMP_NUM_THREADS=1 \
OPENBLAS_NUM_THREADS=1 VECLIB_MAXIMUM_THREADS=1 \
cargo run -p bgremove-bench --offline -- m17-smoke \
  --input path/to/image.png --workers 1 \
  --output runs/m17-performance
```

On macOS/aarch64, omitting `--provider` selects CPU then CoreML. CUDA and
OpenVINO are optional explicit additions via repeated `--provider` flags;
OpenVINO is reported unavailable in this build.

Repeat `--input` for batch image mode. `--max-pixels` is enforced before
inference. Video is intentionally not implemented because no temporal
consistency design has been accepted.

## Evidence

The canonical release run was executed twice with the checked-in
`test_images/reference/1.png` and the local Edge ORT dylib. CPU→CoreML is the
Apple Silicon default. CPU session initialization failed at the verified
model with the exact Edge error `Could not find an implementation for
MaxPool(11) node with name 'MaxPool_4'`; CoreML was unavailable because its
feature is disabled and strict fallback was not enabled. No inference success
or parity is claimed. The report records model-load, first-inference, warm
median/p95, throughput, output-encode, model-byte, RSS and provider fields as
optional and unavailable for that run. Inputs are preflighted from encoded dimensions against a hard
16,777,216-pixel per-image and 33,554,432-pixel aggregate budget before any
pixel decode. The bounded worker pool, cancellation, provider fallback,
capacity/OOM-style rejection, malformed image/model rejection and input-limit
seams are covered by focused unit tests. The release gate is blocked because
runtime output and accelerated parity are unavailable. Weight licence text
files are not provisioned, but SPDX licence identifiers and hashes from the
validated manifests are included in the BOM; this is not claimed as a
completed benchmark.

The release bundle contains `report.json`, `report.sha256`,
`artifacts.manifest.json`, `artifacts.sha256`, `.m17-owned`, `Cargo.lock`, `model-bom.json`,
`code-dependencies.json`, copied model manifests and
`THIRD-PARTY-NOTICES.txt`. The manifest covers every final bundle file except
itself and its checksum; `report.sha256` covers the report and
`artifacts.sha256` covers the manifest, avoiding a circular hash. Code and
model-weight licence metadata are separate, and the release gate forbids
untracked or auto-downloaded weights.

The explicit release model set is `m17-u2net-approved-companions-v1`: the
executable U2-Net manifest plus the approved IS-Net, TRACER and BiRefNet
companion manifests. Synthetic, unavailable and unapproved manifests are not
packaged; the model BOM records this fixed set and copied-manifest equality.

CPU/runtime output parity remains not-run until both CPU and an accelerated
provider produce successful outputs on the same input.
