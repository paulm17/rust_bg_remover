# M14 — Prompted SAM subject selection

M14 adds a typed, source-contract SAM encoder/decoder path in
`bgremove-ort::sam`. It is deliberately separate from the automatic arena:
prompted runs are labelled human-assisted and centre-point defaults are not
automatic leaderboard candidates.

## Contract

The adapter follows `projects/python/rembg/rembg/sessions/sam.py` from rembg
commit `030a9ed79dbfcf8c58a1dc15a8dca3ccd2355709` (SAM source SHA-256
`524bccb7b54acd3979d025e0451334e7a9d0d7e4cd4ce81007b8c1822b827b7d`).
Canonical pixel coordinates are transformed once by the explicit
`SamTransform`; no generic pipeline transform is accepted at that boundary.
Its scale is exactly `min(1024/original_width, 684/original_height)` and
the affine canvas is top-left anchored. Restoration samples decoder masks at
`(x*scale,y*scale)`, matching rembg's inverse-matrix-to-warp-affine contract.
The encoder uses the rembg 684x1024 HWC float32 canvas. Decoder prompts use
positive/negative labels 1/0, ordered box labels 2/3, the padded point with
label -1, `mask_input` `[1,1,256,256]`, `has_mask_input` `[1]`, and
`orig_im_size = [684,1024]`. Prior masks are finite and exactly 256x256.

Every decoder candidate retains restored logits, binary selected mask, quality
score, and low-resolution logits. `HighestQuality` is the default typed policy
with deterministic lowest-index tie-breaking. `SourceCompatibleUnion` is an
explicit parity-only policy and is never silently used by the quality path.

## Model registry and gate

The supported B/L/H fp32 and quantized encoder/decoder pairs are registered as
external manifests. The rembg adapter is recorded as MIT source code while the
Segment Anything model weights are recorded separately as Apache-2.0. They are
unapproved with `sha256 = "unavailable"`; each also records rembg's published
MD5 release checksum. ViT-H additionally declares its three published encoder
shards and rembg-assembled combined sidecar, all fail-closed until provisioned
and SHA-256 verified. `verify_model_hash` therefore fails before session
creation. No checkpoint is downloaded or checked in. The exact real-weight gate
remains unavailable. The Level-2 fixture uses a small
checked-in synthetic encoder/decoder ONNX pair (`m14_sam_synthetic_*`) to
exercise the actual two-session ORT flow while executing the pinned source
prompt helpers; it is not real-weight quality evidence.

## Evidence

`tests/fixtures/m14/run_authoritative.py` runs the pinned source twice with
SciPy's actual `scipy.ndimage.map_coordinates` and writes compact, hashed
samples plus packed final masks for both prompt cases across portrait,
landscape and square geometry. Deterministic synthetic arrays are reconstructed
by the Rust consumer. It checks the full encoder-input digest and full final
selected/source-union bitmaps; compact source-produced samples cover raw and
low-resolution candidate logits, embedding, and restored tensor stages,
while prompt inputs, priors, and quality scores are checked for every case.
The Python environment and dependency lock are recorded in the report.
The tracked M14 evidence set is exactly 1,484,579 bytes across 94 files; the
reference directory is approximately 1.6 MB and the synthetic ONNX pair is
approximately 4 KB per graph.

Rust consumes those fixture bytes in
`pinned_python_fixture_is_consumed_for_prompt_and_mask_stages`; the source
contract gate passes within declared tolerances. This is distinct from the
real-checkpoint comparison, which remains unavailable.

Manual and centre-default prompts are assisted/non-automatic. Coarse
component-derived prompts are typed as automatic-derived, but are eligible for
an automatic record only when the pipeline explicitly declares that derivation;
the report records this separation and the synthetic fixture remains excluded.

## Verification

```text
<pinned-python-3.12-with-scipy>/bin/python tests/fixtures/m14/run_authoritative.py
cargo test -p bgremove-ort sam
cargo test -p bgremove-models m14_sam
cargo fmt --all -- --check
cargo run -p bgremove-ort --example sam_synthetic_smoke
```

The synthetic smoke was run twice with `libonnxruntime.1.23.2.dylib`, SHA-256
`92500010659b052368797e30c1841956b0efd699a8061ef8b3b25f27449c86e7`, and
produced identical output (`stdout_sha256 =
e3960fd04f0cde8d70c5ddc2d401e6ffaeb19ef361f8175cf583ff251349e5f0`). Both
runs exercised two verified ORT sessions and reported three decoder candidates
with deterministic selected index 1. The real encoder/decoder smoke remains
unavailable because approved external weights are not provisioned. `SamSegmenter`
does not implement the generic `Segmenter` trait until the core pipeline has a
coordinate-aware prompt transform; its standalone prompted API is the safe
integration surface.
