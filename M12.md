# M12 — ViTMatte refinement

Implemented in `bgremove-ort` as `VitMatteRefiner` and the
`vitmatte_preprocess`/`restore_vitmatte_alpha` contracts.

- RGB uses Pillow-compatible bilinear resize; trimap uses nearest resize.
- Input is fixed `[1, 4, 1024, 1024]`, NCHW, RGB then trimap, values in
  `[0, 1]`, with no mean/std transform.
- Alpha output is clipped, converted to uint8 like rembg, restored with
  Pillow-compatible bilinear resize, and returned as alpha only.
- One process cache entry is held per selected variant. Foreground colour is
  deliberately left to the configured foreground estimator.
- All four real variants are registered with exact upstream SHA-256 values,
  but their checkpoint files are not locally available and their manifests are
  unapproved; no default is selected and no network download occurs.
- A deterministic synthetic ONNX fixture exercises the actual ORT path. It is
  not evidence of real-model quality.
- The tracked authority under `runs/m12-vitmatte/authority/` executes the
  pinned Python `matting.py` function itself with only `_get_session` patched
  to a local capture wrapper. Rust smoke compares full input, raw-output, and
  restored-alpha artifacts against that authority.
- Real edge-category and resource metrics remain null/unavailable until the
  four approved checkpoints are supplied; the synthetic run does not stand in
  for those metrics.

The acceptance report must compare all four approved checkpoints using
edge-category quality plus checkpoint size, cold-start, steady-state latency,
and peak memory. Aggregate alpha IoU alone is explicitly insufficient.
